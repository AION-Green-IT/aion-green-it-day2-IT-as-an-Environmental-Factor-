========================================================================
AION GREEN IT — MODULE 1 · WORKSHEETS BUILD SPEC
Build prompt for Claude Code · Version 1.0 · English (international)
========================================================================

You are building 4 learner worksheets (Microsoft Word .docx files) for
the AION Green IT Module 1 course. Each worksheet supports one task from
the curriculum. When the app in this repo is deployed, the worksheets
are what learners actually fill in.

This spec is authoritative. Worksheets that meet every clause here pass.
Worksheets that skip clauses fail, even if they look nice.

Read this whole spec end to end before writing any code. Then produce
all 4 worksheets in a single pass, verify them visually, and commit them
to the repo. Do NOT ask clarifying questions unless a concrete
requirement contradicts itself.

If this spec ever disagrees with the app playground build prompt
(AION_GreenIT_M1_ClaudeCode_BuildPrompt.txt), the app build prompt wins
on APP behaviour and this spec wins on WORKSHEET content. Where the app
has evolved past the build prompt (e.g. NordCom is now a 9-finding
board, not a 5-tab dashboard), the LIVE app is truth and both prompts
must be updated to match. See section 6.

------------------------------------------------------------------------
0. WHO THIS IS FOR
------------------------------------------------------------------------

- **Audience**: international CXO / senior leadership learners. Adult,
  self-paced, scannable. Zero prior Green IT knowledge assumed.
- **Setting**: a 1-day workshop with 1-hour input blocks followed by
  1–2-hour task blocks. Each worksheet supports one task block.
- **Language**: English only. Even if the classroom is bilingual, do
  not translate. The playground is English, the worksheets are English,
  the answer keys are English.
- **Delivery**: worksheets are printed OR opened on a laptop next to
  the playground. Both must work.

------------------------------------------------------------------------
1. NON-NEGOTIABLES  (violate any and the build fails)
------------------------------------------------------------------------

N1. **English only.** Every string in every worksheet is English. Do
    not translate. Do not paraphrase content that appears in the app.

N2. **Self-contained.** Every worksheet MUST contain a "Reference
    Material" box that carries every fact from the app that the
    worksheet needs. A learner with only paper and pen must be able
    to complete every section. The app is a tool for exploration, not
    a requirement.

N3. **Verbatim copy from the app.** Any content that appears on the
    app (hotspot facts, initiative texts, condition texts, finding
    texts, measure texts, points, action-area names) is copied
    VERBATIM into the worksheet's reference material and any answer
    key. If you find yourself wanting to shorten a sentence, don't.

N4. **No internal IDs exposed to the learner.** The app has internal
    ids like `hs-server-room`, `ctx-elec-rising`, `init-A`. These are
    for developers, not learners. Worksheets refer to app elements
    by their on-screen label ("Server room", "Electricity meter",
    "Initiative A — New devices"). Worksheets may introduce their OWN
    stable references (F1, F2, AA1, M1 — see section 11) so answers
    can be cited compactly, but these are worksheet-side conventions,
    not app-side ids.

N5. **Every section declares its grading.** Every section MUST open
    with a full-width marker line reading either:
       "OBJECTIVE — marked right / wrong"    (green background)
       "JUDGED — marked with a rubric"       (amber background)

N6. **Every section declares where to look.** Every section MUST open
    (right after the marker line) with either:
       - a "IF YOU HAVE THE APP" callout (purple bar), when the section
         benefits from opening the app, OR
       - a "WHERE TO LOOK" note (soft lilac), when the section is
         answered from the sheet alone.
    Never both. Never neither.

N7. **Objective sections must be objectively markable.** If a section
    is marked as OBJECTIVE (green), there must be an answer key
    against which every learner answer can be checked. If the answer
    involves judgment ("assess impact"), it is JUDGED (amber), not
    OBJECTIVE. Do not label a judgment section as objective to make
    it look easier.

4. SHARED HELPERS  (ws_helpers.js API)
------------------------------------------------------------------------

Every build script imports from ws_helpers.js. The helper library
exposes at minimum the following (names are frozen — do not rename):

Tokens (exported constants):
  NAVY, PURPLE, LILAC, INK, ASH, LINE, OBJ, JDG, REF, REFBAR, FONT,
  VERCEL_ROOT, TOTAL_W

Text primitives:
  p(text, opts?)                      simple paragraph
  pMixed(runs[], opts?)               paragraph with several styled runs
  link(url, label?, opts?)            external hyperlink (purple, bold,
                                      underlined)
  pWithLink(prefix, url, label, opts?)  prefix text + link in one line
  h1(text)   h2(text, opts?)   h3(text, opts?)
  spacer(sizeTwips = 120)

Table primitives:
  cellBorders(colorHex = LINE)
  cell({ text, bold?, italics?, shading?, width?, align?, color?,
         size?, children? })
  cellMulti(paragraphs[], opts?)
  headerRow(cells[], shading = LILAC)

Callouts:
  findItBox(routeText, howText)
      Renders a purple-bar / lilac-body callout with two lines:
        "IF YOU HAVE THE APP · <routeText>"
        "HOW · <howText>"
      Use ONLY when the section benefits from opening the app.

  locationNote(text)
      Renders a soft lilac full-width note with the prefix
      "WHERE TO LOOK · <text>".
      Use for sections that do NOT need the app.

  markerLine(kind)     kind ∈ {"OBJECTIVE", "JUDGED"}
      Full-width single-cell table.
      OBJECTIVE → green (OBJ) bg with OBJ-FG text
                  "OBJECTIVE — marked right / wrong"
      JUDGED    → amber (JDG) bg with JDG-FG text
                  "JUDGED — marked with a rubric"

  referenceBox(title, paragraphs[])
      Renders a gold-bar / amber-body callout with:
        Header:      "REFERENCE MATERIAL · " (bold, REFBAR)
                     + title (bold, NAVY)
        Disclaimer:  italic ASH:
                     "You do not need the app for this worksheet —
                      everything you need is printed below. The app
                      is a nice-to-have if you want to explore
                      visually."
        Body:        the provided paragraphs.

Reference-content primitives:
  refItem(label, body, extra?)
      • label — body  extra (italic ASH)
  refBullet(text, opts?)
      • text

Header info card:
  headerInfoTable(rows[])
      Two-column table (2400 / 6960 twips) with lilac left cells and
      paper right cells. Each row is [label, value, isLink?]. If
      isLink is true, the value renders as an ExternalHyperlink.

How-to list:
  howToList(items[])
      Numbered list with purple bold numerals.

Document build:
  buildDoc(title, description, children)
      Returns a docx Document with the correct page setup and default
      styles (Calibri 11pt).
  writeDoc(doc, outPath)
      async — writes the .docx buffer to disk.

DO NOT ADD:
  - shadcn-style helpers
  - "smart" defaults that change spacing over time
  - PDF export inside the helper (verification lives outside)

5. ANATOMY OF EVERY WORKSHEET  (the fixed order — do not rearrange)
------------------------------------------------------------------------

Every worksheet's document `children` array follows this order:

  1. h1(<worksheet title>)
  2. pMixed with meta line: "Task N · Level X · Case: <company>"
  3. headerInfoTable(...)
       Rows in this order (every row exactly once):
         [ "Module",           "Module 1 (Day 1) — Green IT ..." ]
         [ "Level",            "L1 · Knowledge — ..."  ]  (or L2/L3)
         [ "Playground page",  <URL to specific case page>, true ]
         [ "Full playground",  <URL to root>, true ]
         [ "Estimated time",   "~ N minutes ..." ]
         [ "How it is marked", "<one-line description>" ]
         [ "Self-contained",   "Yes. ..." ]
         [ "Name / Group",     " " ]
         [ "Date",             " " ]
  4. h2("How to use this sheet") + howToList(4 items — see section 8.6)
  5. h2("Reference material — everything you need to complete this
        worksheet") + referenceBox(...)
  6. h2("Playground map — where each section takes you (if you use
        the app)") + p(intro) + <playground map table>
  7. For each section S (A, B, C, ... in order):
        h2("Section S · <title>")
        markerLine(<OBJECTIVE or JUDGED>)
        spacer(80)
        findItBox(...) OR locationNote(...)      (choose one — N6)
        spacer(80 or 100 or 120)
        Section-specific: definitions, hints, one or two paragraphs
        Section-specific: the fill-in table
        Optional: a check row inside the table
  8. h2("How this is marked") + p(intro) + <rubric table>
  9. h2("One-line closing") + pMixed pedagogical note (italic + normal)

7. GRADING & MARKER CONVENTIONS
------------------------------------------------------------------------

7.1  Two grading modes only:

  OBJECTIVE — the answer is a fact or a computation. There is a single
  correct value. Marker line bg is OBJ (green).
    Examples: copying a fact verbatim; counting hotspots in a
    category; ticking an obstruction; satisfying a self-check
    arithmetic constraint.

  JUDGED — the answer is a decision or a written argument. Marks come
  from a rubric. Marker line bg is JDG (amber).
    Examples: writing an assumption + business consequence; picking
    a first step and defending it; naming a trade-off.

7.2  Rubric scales:

  L1 tasks → 2-point per section (Full = 2 / Partial = 1 / None = 0).
             Total possible = 2 × (number of sections).
  L2 tasks → 4-point per section (Executive-ready = 4 / Solid = 3 /
             Partial = 2 / Missing = 1).
  L3 tasks → 4-point per section (same scale as L2, but wording
             raises the bar: "executive-ready" means both a decision
             AND a rule the next person could apply).

7.3  Rubric table format:
  - 4 columns for L1 (Section, Full, Partial, None)
  - 5 columns for L2/L3 (Section, 4-Executive-ready, 3-Solid,
    2-Partial, 1-Missing)
  - Header shading: green tint for the full/executive column, amber
    tint for solid/partial, red tint for missing.

7.4  Every rubric row describes OBSERVABLE things, not adjectives.
  Bad:   "Deep analysis"
  Good:  "All five assumptions cite at least one hotspot label AND
          name a concrete business consequence."

------------------------------------------------------------------------
8. NAVIGATION CONVENTIONS
------------------------------------------------------------------------

8.1  Every worksheet has a **Playground map** table right after the
     Reference Material box. Columns:
       Section | Where to look in the app | What you do there
     Fill every section (A, B, C, ...) with either:
       - a concrete panel description if the section benefits from
         the app, OR
       - "No app viewing needed." if the section is answered from
         the sheet alone.
     The Playground map is the single overview so learners never hunt.

8.2  Every section has ONE (and only one) of:
       findItBox(routeText, howText)     — for app-viewing sections
       locationNote(text)                — for paper-only sections

     `routeText` for findItBox must include the full URL AND the
     panel name AND, where relevant, the location on the page.
     Example:
       "https://aion-green-it-day1-green-it-as-a-le.vercel.app/case/
        mediprint/ — the MediPrint building illustration (right side)."

     `howText` must include the interaction (click / read), the item
     count, and the fallback ("Show all facts as list" toggle, or the
     Reference Material box on this sheet).

8.3  Never expose internal ids (like `hs-server-room`) to the learner.
     Use on-screen labels only.

8.4  Worksheet-side citation labels are allowed and encouraged:
       F1..F10   for findings (used in Worksheet 3 and 4)
       AA1..AA4  for action areas (used in Worksheet 3)
       M1..M6    for measures (used in Worksheet 4)
       C1..C5    for conditions (used in Worksheet 2)
     These are worksheet references, not app ids. Learners can cite
     them compactly in their justifications.

8.5  When a section is followed by another section that reuses the
     same rows (e.g. Section D in Worksheet 1 reuses the 9 hotspots
     from Section A), pre-fill the row labels so the learner does not
     have to copy them twice.

8.6  The How-to list has exactly 4 items:
       1. "Read the Reference Material box below. It carries ...
           you can complete this worksheet from paper alone."
       2. "Optional: open the <case> page (link in the header). ..."
       3. "Follow the section order: A → B → C → ..."
       4. "This is a case-based / L1 / L2 / L3 task. The examiner
           is looking for ..."
     Item 1 always states the self-contained property. Item 2 always
     positions the app as optional. Items 3 and 4 are task-specific.

------------------------------------------------------------------------
9. SELF-CONTAINED PRINCIPLE  (the reference material box)
------------------------------------------------------------------------

Every worksheet has ONE `referenceBox(title, paragraphs)` call right
after the "How to use this sheet" section. Its content includes,
at minimum:

  9.1  A one-sentence "situation" paragraph, verbatim from the app's
       company brief. This is what the learner would see at the top
       of the case page.
  9.2  Every fact / initiative / condition / finding / measure that
       any section of THIS worksheet references. Nothing more, nothing
       less. If a worksheet does not use context conditions, do not
       include them.
  9.3  Where relevant, the topic-area category chip (in brackets after
       the fact): "[Energy]", "[Resources · Emissions]", etc.
  9.4  Any hard constraint that governs the worksheet (e.g. Auron's
       "16 points requested, 10 points available") is stated in bold
       DANGER-coloured text inside the reference box.

The referenceBox includes an italic ASH disclaimer that the helper
adds automatically — do not repeat it manually.

Header info:
  Playground page: {VERCEL_ROOT}/case/mediprint/
  Level:           L1 · Knowledge — observation, structuring,
                   common sense
  Time:            ~ 30 minutes (after the 60-minute knowledge input)
  Marking line:    "Sections A, B and the tick column in D = OBJECTIVE
                   (right/wrong). Section C and the reason column in
                   D = JUDGED (rubric)."

Reference material title:
  "MediPrint Solutions — the nine hotspots and three context
   conditions, as shown in the app."

Reference material contents (from section 11.A):
  - Company brief (one paragraph)
  - The nine hotspots as refItem(label, fact, "[category chips]")
  - The three context conditions as refBullet(text)

Sections:
  A · Hotspot log       OBJECTIVE  (findItBox)
      A1 · Hotspots on the hero
          Table columns: # | Hotspot label (on screen) | Fact from the
             modal (copy verbatim) | Primary category | Secondary
             category (if shown)
          9 pre-filled rows with the labels (Server room ... Project
             intake board). Learner fills fact and categories.
      A2 · Context conditions (the "Context" panel)
          Table columns: # | Context statement (copy the pill wording
             verbatim)
          3 rows, learner fills.

  B · Category tally    OBJECTIVE  (locationNote — no app needed)
      Table columns: Category | Code | Count as PRIMARY | Count as
         SECONDARY | Total touches
      5 rows (E, R, Em, U, G), learner fills counts.
      Check row: "the PRIMARY column must sum to 9 ..."

  C · Five assumptions  JUDGED     (locationNote)
      Table columns: # | Assumption (one sentence) | Supporting
         hotspot label(s) from Section A | Business consequence if
         left as-is (one sentence: cost / risk / reputation /
         regulation / people)
      5 empty rows.
      Instruction: no two assumptions may rest on exactly the same
         hotspot(s).

  D · Operational vs Strategic   OBJECTIVE (tick) + JUDGED (reason)
      (locationNote — reuse hotspots from A in same order)
      Table columns: # | Hotspot | Operational | Strategic | Short
         reason (one sentence)
      9 pre-filled rows with hotspot labels + □ characters in the
         two tick columns.
      Check row: "exactly one ✓ per row. The two columns together
         must contain 9 ticks."
      Working definition paragraph before the table:
        "Operational = the impact lives in one unit, one cycle, or
         one device, and can be fixed by the current process owner.
         Strategic = it requires a policy, cross-functional authority,
         or a change in how decisions are taken."

Rubric (L1, 2-pt scale, 4 rows for sections A / B / C / D).

Closing (italic + normal, one line each):
  "This task trains systemic observation. If two participants
   disagree in Section A or B, one of them has misread the reference.
   If two participants disagree in Section C or in the D reasons,
   both may be right; what is marked is how the reasoning is built."

======================================================================

Header info:
  Playground page: {VERCEL_ROOT}/case/mediprint/
  Level:           L1 · Knowledge — prioritisation and decision under
                   uncertainty
  Time:            ~ 45 minutes
  Marking line:    "Sections A, B, C, E-check = OBJECTIVE. Sections
                   D, E-pick, F = mix of OBJECTIVE (E-pick) and
                   JUDGED (D, F)."

Reference material title:
  "MediPrint — the three initiatives and five general conditions,
   as shown in the app."

Reference material contents (from section 11.B):
  - Situation paragraph
  - Three initiatives (A / B / C) as refItem
  - Five general conditions as refItem(C1..C5, text)

Sections:
  A · The three initiatives (copy)      OBJECTIVE  (findItBox)
      Table columns: Initiative (A/B/C) | Short title | Full
         description (copy verbatim)
      3 rows.

  B · The five general conditions (copy) OBJECTIVE (findItBox)
      Table columns: Condition # | Wording (copy verbatim)
      5 rows.

  C · Constraint matrix (right/wrong!)  OBJECTIVE (locationNote)
      Table columns: C# | Condition (copy short-form) | Obstructs A?
         | Obstructs B? | Obstructs C? | # ticked
      5 rows with □ characters in the three obstruction columns.
      Totals row at the bottom.
      Hint paragraph after the table (italic ASH):
        "A limited budget hits a big capital outlay harder than a
         policy-writing exercise. A short-term-results demand
         penalises the slowest-to-show initiative. A sceptical
         purchasing team punishes the initiative that lands squarely
         on their desk."
      Answer key (used later by the instructor Answer Key doc):
        C1 budget limited            → A (heavy capital)
        C2 data incomplete           → A (needs baseline first)
        C3 board wants short-term    → C (governance is slowest)
        C4 IT staff capacity         → B AND C (both need staff time)
        C5 purchasing sceptical      → B (rules land on purchasing)

  D · Score each initiative (5 criteria)  JUDGED (locationNote)
      Table columns: Initiative | Impact (H/M/L) | Feasibility (H/M/L)
         | Acceptance (H/M/L) | Strategic leverage (H/M/L) | Time
         required (weeks / months)
      3 rows (A, B, C).
      Working definitions paragraph before the table.

  E · Priority decision   OBJECTIVE (locationNote)
      Table columns: Decision element | Write your answer here
      3 pick rows with "Circle:  A   /   B   /   C" plus a self-check
         row: "the three circles across the three rows must be A, B
         and C — no repeats."
      Answer key: first pick = C (governance/steering committee),
        per the pedagogical logic "build management capability before
        larger investments" that appears in the NordCom model
        solution. Second and third picks are graded on internal
        consistency with Sections C and D.

  F · Justification, missing info, risks  JUDGED (locationNote)
      Table columns: Question | Your answer
      5 rows:
        F1 justify first-priority in 1 sentence citing ≥1 condition #
        F2 justify in 1 more sentence citing ≥1 Section D score
        F3 name TWO pieces of missing information
        F4 how to decide despite missing info (1 sentence)
        F5 name TWO risks of the chosen first-priority initiative

Rubric (L1, 2-pt scale, 5 rows for A+B / C / D / E / F).

Closing:
  "A priority is a claim about time, not about quality. The
   pedagogical trap in this task is to pick the initiative that
   sounds the greenest instead of the one that makes the other two
   decidable next."

10.C  WORKSHEET 3 · Task 3 · NordCom · L2
      "Green IT at NordCom: from findings to a first step"
      dist/Worksheet3_NordCom_L2.docx
======================================================================

Header info:

                   solution
  Time:            ~ 90 minutes (roughly two units)
  Marking line:    "Rubric-graded on a 4-point scale (Executive-ready

  - Nine findings F1..F9 as refItem(F#, text, "[category chips]")

14. COMMON PITFALLS  (things reviewers catch)
------------------------------------------------------------------------

P1  Silently translating a fact. Do not translate. If a fact contains
    an unfamiliar term, keep the English word and let the classroom
    ask.

P2  Exposing developer ids. `hs-basement`, `ctx-elec-rising`,
    `init-A` are dev references and MUST NOT reach the learner. Use
    the on-screen label. Worksheet-side references (F1, AA1, M1)
    are fine because they are introduced on the sheet itself.

P3  Judging an objective section. If you mark a section OBJECTIVE
    but need adjectives to grade it, it is JUDGED — change the
    marker line and the rubric row.

P4  Skipping the Reference Material because "the app has it". Do not
    skip it. Self-contained is the whole point.

P5  Using tooltips-in-cells instead of a check row. A learner cannot
    hover a printed page. Put the self-check as a visible full-width
    row.

P6  Rubric adjectives. "Deep analysis", "insightful", "elegant" — all
    unmarkable. Use observable descriptors: "cites at least one F#",
    "names a trade-off", "states a revisit trigger".

P7  Findable-but-not-checkable. A section that asks for judgment
    against an answer key nobody wrote is a judgment section with a
    missing rubric. Either write the answer key OR change the
    grading mode.

P8  Forgetting the hyperlink flag. In headerInfoTable rows, remember
    to pass `true` as the third element for URL rows or they render
    as plain text, not clickable links.

P9  Silently drifting from the app. If a reviewer opens the live URL
    and finds different wording than the reference material, the
    worksheet has drifted. Update ws_content.js. Do not "sync later".

P10 Padding to hit a section count. If a task naturally needs 3
    sections, use 3 sections. Do not add a filler section to match
    another worksheet's shape.
